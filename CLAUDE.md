# Working on this repo

Excel project planner, generated by Python (`planner/`, entry point `scripts/build_planner.py`). Read
`docs/ARCHITECTURE.md` before changing formulas.

## Rules (from the project owner; they apply to every change)

- **Robust, editable formulas.** No A1 cell addresses in formulas. Use Excel Table structured references
  (`[@Column]`, `Table[Column]`), defined names, or `ROW()`/`COLUMN()` offsets from a named anchor, so inserting
  or moving rows and columns never needs a formula tweaked. Conditional formatting, data validation and chart
  series are the only exceptions, because Excel requires A1 there. Never use a range ending at "the row above"
  (`$X$5:X9`): it doesn't grow when a row is inserted directly above. `RealRowEditTest` checks real insertions.
- **Scheduling rule:** a predecessor must be a detail task listed above its successor (forward and backward
  passes stay consistent); Link Check explains violations. Reading another row's *calculated* value uses OFFSET
  from the header cell, the one allowed volatile function (see docs/ARCHITECTURE.md).
- **Well structured for people to edit later.** One formula per table column; short, plain column names; helper
  columns prefixed `_`; inputs (blue) separate from formulas (grey). Python code: one module per sheet, small helpers,
  docstrings that say why.
- **Performance is tested on every PR.** Run `scripts/perf_check.py` on the sample and the 1,000-task stress
  workbook (CI does this). Don't add volatile functions (`OFFSET`, `INDIRECT`, `TODAY`, `NOW`, `RAND`, `CELL`,
  `INFO`) beyond the allow-list in `perf_budget.json`. Don't add whole-column references or per-task `SUMPRODUCT`s in report grids (use
  `SUMIFS`), and don't put formulas in cells that only need colouring. Report the before/after numbers in the PR description. Raise a budget only
  with a stated reason.
- **Excel 2019 / Microsoft 365 is the minimum.** Of the newer functions only `_xlfn.MINIFS` / `_xlfn.MAXIFS` are
  allowed (a test enforces it), plus `_xlfn.TEXTJOIN` in the Release 1.0 build; no Microsoft 365-only functions such
  as XLOOKUP, FILTER or LET, except in the Microsoft 365 edition (`--release m365`, `release-1.1-m365/`), which is
  built without `--recalc` and checked by structure (tests/test_m365.py) and in Excel.
- **Release 1.0 is frozen** (`--release`, `release-1.0/`): fixes only. Template 1.1 (`--release 1.1`,
  `release-1.1/`) adds features behind `core.v11()`; template 1.2 (`--release 1.2`, `release-1.2/`) behind
  `core.v12()`, with its look in planner/theme.py.
  A change to shared code must leave the classic workbooks at the root unchanged unless that is the intent.
- **Macros and Python are optional for users.** The `.xlsx` must work in Excel alone (desktop, web, iPhone).
  Macro or tool features only automate what the workbook can already do by hand.

match the build.
